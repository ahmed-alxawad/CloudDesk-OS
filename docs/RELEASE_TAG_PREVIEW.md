## Proposed annotated tag message

```
CloudDesk-OS v1.0.1-rc.4 (release candidate)

Patch release candidate on top of v1.0.0, prepared on
engineering/v1-true-closure. v1.0.0 itself is unchanged and remains the
last tagged release; this candidate is not yet published.

Supersedes v1.0.1-rc.3 (tagged and pushed at 43b31a9, but its hosted
release-attestation workflow run failed before producing any
attestations -- 0/11 subjects attested, no GitHub Release created).
rc.3 is not altered; it remains frozen, immutable public history.
v1.0.1-rc.2 (6b1eaa8) and v1.0.1-rc.1 (89bfe46) remain frozen and
superseded for their own separate, earlier reasons.

What rc.4 corrects on top of rc.3 (all confirmed live on GitHub's
hosted runner, not merely locally):
- Platform checksum manifests (dist/linux-x86_64-{glibc,musl}/SHA256SUMS)
  are now generated by packaging/build-release.sh and
  packaging/build-release-musl.sh themselves -- this is exactly what
  rc.3's hosted workflow run failed on, since neither script previously
  wrote that file and local manual verification always created it by
  hand as an uncommitted step.
- Ordinary CI's Rust toolchain pinned to 1.97.1 (closing a
  clippy-lint toolchain-drift failure).
- Three flaky-under-hosted-conditions test fixes: test-runtime-fixture
  is now built explicitly before the workspace test suite runs; a
  filesystem-race negative control was rewritten as a fully
  deterministic, zero-timing-dependence reproduction; three
  ffmpeg-spawning media tests are now serialized against each other.

Known, explicitly non-blocking: ordinary CI's Playwright browser E2E
tests still fail because Playwright's browser binaries have never been
installed on the CI runner -- a separate, pre-existing CI-infrastructure
gap unrelated to the release-attestation workflow, tracked as a
follow-up rather than fixed in this candidate.

Highlights carried forward from rc.1/rc.2/rc.3 (no application/product
code changed since rc.1 -- only licensing, documentation, and
release/installer/CI infrastructure):
- 4 real defects fixed from an independent adversarial audit of v1.0.0
  (CLAUDE-NIGHTMARE-001..004), including a CRITICAL SSH host-key
  verification bypass.
- Native musl release artifact and OpenRC service-lifecycle support for
  Alpine Linux, alongside the existing glibc artifact covering
  Debian/Ubuntu/Fedora/RHEL-family/Arch (Phase 10).
- Fresh adversarial security review (Phase 16): one HIGH-severity
  WebDAV TLS certificate-verification bypass fixed, two HIGH-severity
  dependency vulnerabilities fixed, deterministic filesystem TOCTOU/
  symlink-race regression coverage added (0 escapes), audit
  tamper-evidence tests added, and a real two-origin browser CSRF
  control added.
- Root LICENSE (AGPL-3.0-or-later, canonical unmodified text), a
  fail-closed release-staging validator, a direct-fetch installer, and
  a corrected GitHub repository identity (ahmed-alxawad/CloudDesk-OS).

Full evidence: CLAUDE_NIGHTMARE_REPORT.md, PHASE10_DISTRO_MATRIX.md,
PHASE16_SECURITY_REVIEW.md, PHASE17_RELEASE_PUBLICATION_CLOSURE.md,
RELEASE_NOTES.md.

Known limitations (environment evidence gaps, not product defects):
SELinux enforcing mode, true reboot persistence, and a genuinely
subscribed RHEL 9 environment were not exercised in this project's own
test environment. No release has actually been published to GitHub
Releases yet, and no artifact-signing scheme is implemented yet -- see
docs/RELEASE_INTEGRITY.md and docs/RELEASE_SIGNING_DECISION.md.

Not signed. Not published.
```
